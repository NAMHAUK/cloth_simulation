## Current Goal
- Build the SMPL motion cache playback and browsing milestone.
- Let the running app load an existing `.cache` motion from the motion browser list.
- Let the running app import an AMASS `.npz` motion, convert it to `.cache`, refresh the list, and load it.

## Implementation Details
- Runtime motion flow:
  - On app startup, scan `data/cache` recursively for `.cache` files.
  - Display cache entries as relative paths in the motion browser list.
  - Selecting a cache loads it and starts playback.
  - Pressing the `+` import button opens a file dialog for AMASS `.npz` files.
  - Imported AMASS files are converted to `.cache` through the project-local Python environment:
    - Runtime implementation calls `envs/cloth-sim/python.exe` directly to avoid depending on shell profile or PATH setup.
    - Launch the converter with `QProcess` using separate program and argument values, not a shell command string.
    - Set the converter working directory to the project root.
    - Pass `data/smpl/models` as the converter `--model-dir`.
    - Capture stdout and stderr for logging and UI error messages.
    - Treat these cases separately:
      - process failed to start
      - process crashed
      - process exited normally with nonzero exit code
      - process exited normally with exit code `0`
  - If the selected AMASS file is under `data/amass`, preserve its relative dataset folder under `data/cache`.
  - If the selected AMASS file is outside `data/amass`, write the cache under `data/cache/imported`.
  - The app blocks while conversion is running.
  - If conversion fails, show an error and keep the app running.
  - If conversion succeeds, refresh the cache list and load the generated cache.
- Motion browser overlay UI:
  - App startup should prioritize the OpenGL viewer as the main surface.
  - The motion browser should not reserve permanent layout width beside the viewer.
  - Use a top-left `Motions` toggle button as the collapsed state.

  - Keep `QListWidget` as the scrolling list implementation.

    - Keep button/list visibility and callbacks inside `MotionBrowserPanel`.

- Python converter:
  - Read AMASS keys:
    - `poses`
    - `trans`
    - `betas`
    - `gender`
    - `mocap_framerate`

## Data Structures / Interfaces
- Proposed binary cache format:
  - Magic: 8 bytes, `SMPLCACH`
  - Version: `uint32`, initially `1`
  - FPS: `float32`, initially `30.0`
  - Frame count: `uint32`
  - Vertex count: `uint32`
  - Index count: `uint32`
  - Indices: `uint32[index_count]`
  - Vertices: `float32[frame_count][vertex_count][3]`
- Cache coordinate convention:
  - All `.cache` vertex positions are stored in project world coordinates.
  - Project world uses Y-up.
  - Source AMASS/SMPL vertices are converted during cache generation.
  - Runtime OpenGL code does not apply source-coordinate correction.
- Python converter CLI:
  - `--input`
  - `--model-dir`
  - `--output`
  - `--target-fps`
  - optional `--batch-size`
- Converter process result:
  - `ok`: whether conversion completed successfully.
  - `exitCode`: converter process exit code when available.
  - `stdoutText`: captured converter stdout.
  - `stderrText`: captured converter stderr.
  - `errorMessage`: process-start, crash, or conversion failure summary.
- C++ converter interface:
  - Replace `bool runConverter(...)` with a structured result return value.
  - `MainWindow` should display a concise failure message and include captured stderr/stdout details when available.
- C++ motion browser overlay interface:
  - `MotionBrowserPanel` should keep the existing public data/callback methods:
    - `setMotions`
    - `setCurrentCache`
    - `setMotionSelectedCallback`
    - `setImportRequestedCallback`
  - Add only the small state/control API needed for overlay behavior.
  - Keep layout and visibility changes inside the panel where possible.
  - Expose enough state for `MainWindow` to size the overlay correctly without knowing list internals.
- C++ cache ownership:
  - Store all frame vertices in CPU memory for the first implementation.
  - Upload only the current frame to the GPU VBO.
- C++ camera state:
  - `target`: `Vec3`
  - `yawRadians`
  - `pitchRadians`
  - `distance`
  - last mouse position
  - active mouse button state for orbit/pan
  - near/far plane and field of view constants

## Simulation / Rendering Flow
- App starts with the simulation viewer window.
- App scans `data/cache` and fills the motion browser list.
- The viewer is visible at full central-window size.
- The motion browser starts collapsed as a top-left `Motions` button.
- Pressing `Motions` expands the overlay list below the button without resizing the viewer.
- The expanded overlay covers part of the viewer temporarily, but the viewer remains the central widget and keeps its layout allocation.
- The import `+` button remains fixed at the bottom of the overlay while only the list area scrolls.
- User selects an existing cache, or imports an AMASS `.npz` with the `+` button.
- Existing cache selection:
  - Load cache immediately.
- AMASS import:
  - Run converter as a blocking process when the target cache is missing.
  - Refresh the cache list and load the generated cache after converter exits successfully.
- Per frame:
  - Advance playback time.
  - Select current cache frame.
  - Upload current frame vertices to VBO.
  - Compute `projection * view * model` MVP matrix from the current camera.
  - Draw the static `y=0` grid using the same camera MVP.
  - Draw indexed SMPL body mesh.
- Camera input flow:
  - Apply orbit/pan based on mouse move events while a camera button is held.
  - Apply zoom from wheel events.

- Keep `data`, `envs`, and `vcpkg` directories in place.
- Store SMPL model files under `data/smpl/models`.
- Do not commit or expose licensed SMPL/AMASS data.
- Keep the converter project-local and reversible.
- Keep already applied setup details in this plan while they remain relevant to the current implementation.
- Avoid adding new C++ dependencies unless necessary.
- Prefer simple binary cache over glTF for this milestone.
- Use blocking conversion first for simplicity.
- Implement the camera without adding GLM or other math dependencies in this milestone.
- Keep memory use reasonable:
  - Downsample to `30fps`.
  - Batch SMPL conversion in Python.
  - Store only positions first, not normals/materials.
- Keep the overlay UI simple and avoid adding new dependencies.
- Do not let the motion list permanently reduce the OpenGL viewer area.
- The expanded overlay list should be tall enough to browse several entries but short enough to leave most of the viewer visible.
